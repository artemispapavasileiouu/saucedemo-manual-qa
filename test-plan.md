Test Plan — SauceDemo

1. Project Overview
This project focuses on manual testing of the SauceDemo web application.
The purpose of the project is to practice software testing fundamentals, including test planning, test case design, test execution, defect reporting, and test result documentation.

Application under test: https://www.saucedemo.com/

Testing type: Manual Functional Testing

Project status: In Progress

2. Test Objectives
The main objectives of this testing project are to:
- Verify that the main application features work as expected.
- Validate the login functionality using different types of credentials.
- Verify product listing, sorting, and shopping cart functionality.
- Test the checkout process and its validation rules.
- Identify, document, and report any defects found during testing.
- Maintain clear and structured QA documentation.

3. Scope of Testing

In Scope

The following features will be tested:
- User login and authentication.
- Login validation and error messages.
- Product listing and product information.
- Product sorting functionality.
- Adding products to the shopping cart.
- Removing products from the shopping cart.
- Shopping cart contents and item quantities.
- Checkout form validation.
- Checkout process completion.
- Order confirmation page.

Out of Scope
The following areas are excluded from this project:
- Performance and load testing.
- Security and penetration testing.
- Automated testing.
- Compatibility testing across a wide range of browsers and devices.
- Backend API testing.
- Payment gateway integration testing.

4. Test Approach
Testing will be performed manually through the application's user interface. The following testing techniques will be used:
- **Positive Testing:** Verify that the application works correctly with valid input.
- **Negative Testing:** Verify how the application handles invalid input.
- **Boundary Value Analysis:** Test values at or near input limits where applicable.
- **Exploratory Testing:** Explore the application to identify unexpected behavior.

Test cases will be documented before execution. Each test case will include:
- Test Case ID
- Test Scenario
- Preconditions
- Test Steps
- Test Data
- Expected Result
- Actual Result
- Status

5. Test Environment
Test Environment: Web Browser 
Operating System: To be recorded during execution 
Browser and Version: To be recorded during execution 

6. Test Data
The test data will include:
- Valid user credentials.
- Invalid usernames.
- Invalid passwords.
- Empty login fields.
- Product selections.
- Checkout information.
Test data will be based on the credentials and scenarios provided by the demo application.

7. Entry Criteria
Testing can begin when:
- The application is accessible.
- The test environment is available.
- The test scenarios and test cases have been documented.

8. Exit Criteria
Testing will be considered complete when:
- All planned test cases have been executed.
- The status of each test case has been recorded.
- Identified defects have been documented.
- A Test Summary Report has been prepared.

9. Deliverables
The following QA documents will be produced:
- Test Plan
- Test Cases
- Bug Reports
- Test Summary Report

10. Risks and Limitations
- The application is a demo environment and may not represent a production application.
- Some behaviors may be intentionally implemented for testing purposes.
- The project is limited to manual testing of selected application features.
- Test results reflect the application's behavior at the time of execution.

11. Test Plan Approval
This is a personal QA portfolio project. The test plan is prepared and maintained by the project author.
